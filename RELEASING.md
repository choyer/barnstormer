# Releasing

## Why there are two PKGBUILDs

A PKGBUILD that downloads a tag tarball has to carry that tarball's checksum,
and the checksum does not exist until the tag does. A PKGBUILD committed
*before* tagging therefore cannot contain its own checksum — which is how
`sha256sums=('SKIP')` ends up in a release and integrity checking ends up
silently off.

So the two jobs are split, and neither one can be left as SKIP:

| File | Source | Checksum |
|---|---|---|
| `packaging/PKGBUILD` | the checkout you are standing in | none needed — nothing is downloaded |
| `dist/PKGBUILD` | the tag tarball from GitHub | generated and verified after tagging |

`packaging/PKGBUILD` is what `git clone && cd packaging && makepkg -si` uses,
and it reads the version straight out of the Makefile so it cannot drift.
`dist/PKGBUILD` is generated by `tools/mkpkgbuild.sh`, attached to the release,
and is the copy that goes to the AUR.

## Steps

1. **Bump the version.** `VERSION := x.y.z` in the Makefile — the only place
   it is written down. `--version`, both PKGBUILDs and the artifact names all
   follow from it.

2. **Update `RELEASE_NOTES.md`** — retitle it and put a "Changes in x.y.z"
   section at the top.

3. **Commit, then tag and push.**

   ```bash
   git push origin main
   git tag -a vx.y.z -m "Barnstormer x.y.z"
   git push origin vx.y.z
   ```

4. **Build the binary tarball** in a clean container, so the artifact is not
   shaped by whatever is on your machine:

   ```bash
   docker run --rm -v "$PWD:/src:ro" -w /src archlinux:base-devel bash -c '
     pacman -Sy --noconfirm wayland libxkbcommon alsa-lib
     cp -a /src /build && cd /build && make && make test
     ...'
   ```

   (`pkexec docker ...` if your user is not in the `docker` group. Mount the
   source read-only and stream the tarball out on a spare fd, so nothing in
   the repo ends up owned by root.)

5. **Generate the distribution PKGBUILD** — this is the step that used to be
   forgotten:

   ```bash
   tools/mkpkgbuild.sh
   (cd dist && makepkg --verifysource)     # must print "Passed"
   ```

   The script refuses to write anything unless the tag is pushed, the tarball
   hashes identically on two separate fetches, the tag really contains the
   version it claims, and the resulting checksum is real rather than `SKIP`.

6. **Publish.**

   ```bash
   gh release create vx.y.z \
     dist/barnstormer-x.y.z-x86_64.tar.gz \
     dist/barnstormer-x.y.z-x86_64.tar.gz.sha256 \
     dist/PKGBUILD dist/.SRCINFO \
     --title "Barnstormer x.y.z" --notes-file RELEASE_NOTES.md
   ```

7. **AUR**, once the package is submitted there: copy `dist/PKGBUILD` and
   `dist/.SRCINFO` into the AUR clone and push. They are already correct for
   the tag — no editing, and nothing to remember.

## Checks worth keeping honest

- `make test` — the headless simulation, run under ASAN and UBSan.
- `makepkg --verifysource` in `dist/` — proves the pinned checksum matches
  what GitHub is actually serving today.
- `barnstormer --version` from the built tarball — proves the artifact is the
  version on the box, not a stale build.
